# Scene-first alpha (0.12.0)
The sample opens Scene Composer, not the timeline. Separate background, transparent pose and prop assets form editable scene instances. UI SDK canvas primitives provide transforms, selection, viewport and history. Library-to-canvas insertion uses SDK bindDrag and a bounded drop check; keyboard/click insertion is available. Native rendering is canvas drawing, not a replacement UI toolkit. Motion presets are layer transforms, not skeletal animation. Live scene clips evaluate the same renderer in the timeline; still-to-comic creates a snapshot, not a live link. Existing example workspaces receive missing scene assets once without replacing edited pages. Local browser persistence only. Sprite animation, pose libraries, keyframe lanes, audio, AI video and server persistence remain out of scope for this slice.

## 0.13.0 — focused workspace and manual motion
Scene Composer owns its full workspace. Manual animation uses integer project frames and normalized transforms; enable Animate at playhead, scrub, then move/resize or change rotation/opacity, or set a key. Linear interpolation, explicit key removal and frame markers are supported. Manual keys override presets; clearing keys restores presets. Pose cycling uses ordered pose images and FPS, not skeletal rigs. The example includes two additional pose images. Existing scene edits and timeline are retained. No audio, generated video, advanced easing or server persistence yet.

## 0.14.0 — workflow handoff
Appending a scene selects the new clip and seeks to its first frame. Open scene source returns to the corresponding scene. Still to comic selects the newly created page. The composer remembers the active scene while navigating within a project. Click/drag insertion suppresses duplicate click events after a drag. Added compact workflow hints. Still-to-comic remains a flattened snapshot; no live comic link yet.

## 0.15.0 — character actions
Per-character reusable action definitions contain ordered pose asset IDs, FPS and loop/once playback. The example contains authored SVG pose sequences: idle, walk in place, jump, talk gesture and Observer signal pulse. These are simple frame-by-frame samples, not skeletal animation or lip sync. Actions copy their frame sequence into the scene object, so subsequent library changes cannot silently change an existing scene. Custom cycles can be saved as reusable actions. Invalid or cross-character asset references are rejected. Existing example projects gain only missing action assets and definitions. Position keyframes remain independent of pose playback. No rigging, automatic walk path or generated action assets.

## 0.16.0 — connected project workflow
The main navigation groups Plan, Prepare, Compose, Publish. Storyboard opens the existing linked composition or creates it with the planned cast's first usable poses; no background is guessed. Asset Library imports typed backgrounds, character poses and props; Use in scene targets the named current composition (or creates one when absent). AI is an optional preparation tool. Scene publishing reopens an existing linked video clip instead of implicitly appending duplicates. Comic snapshots carry sourceCompositionId and expose a return link; they remain snapshots, not live panels. No automatic replacement of existing pages/clips. Existing projects remain intact.

## 0.16.1 — UI regression repair
v0.16.0 browser QA showed overlapping navigation hit targets: Generate intercepted Assets. Use intrinsic grid columns and non-shrinking controls instead of letting SDK button widths collapse in nested flex layout. Composer now separates scrollable asset and property panes from a bounded canvas/playback workspace on desktop; compact screens retain scrolling with stage first. No changes to project data or features. Added pointer hit-target and viewport visibility regression tests. Consulted official React Button and Toolbar documentation; retained SDK web.css and parts.

## 0.16.2 — canvas density after screenshot review
Visual review of the 0.16.1 responsive screenshots showed that the 720px-high desktop artboard was too small despite passing viewport checks. Scene selection now shares the composer header; scene name, storyboard summary, cast and step status moved into Inspector. Desktop regression test additionally requires a portrait artboard of at least 320px height at 1440×900 and 220px at 1280×720. No model or feature changes.
