# UI SDK native migration (0.6.0)

Official references consulted: https://ui-sdk.dev/docs/react/components/select, /input, /textarea, /checkbox, /field, /tabs, /slider, /resizable, /scroll-area, /file-input, /progress, /toggle (relative to the components URL). Public docs search was accessible; direct package documentation could not be read in the authoring environment. CI verifies its presence.

Migrated: native text inputs and textareas, select/option, checkboxes, file pickers, export progress, production tabs, timeline zoom, workspace library and inspector scroll areas, visibility toggles and vertical workspace/timeline resizer. Actual SDK components and composition wrappers, not CSS imitations. Removed global button/input/select/textarea styling overrides; retained layout styles and the official web.css import.

Remaining custom surfaces: timeline clip placement/drag/trim/scrub, comic panel placement/drag, app navigation layout, responsive overlay behavior and horizontal side pane layout. These use domain logic and/or SDK bindDrag where applicable. createSpans, selection, horizontal Resizable, Dialog, richer asset Tree are not implemented in this pass. Numeric properties now use the documented NumberInput composition. The first browser QA run passed 3 of 4 tests and found an inspector visibility regression on mobile. The follow-up separates compact overlay state from desktop pane visibility; rerun E2E to confirm. Visual parity with official examples requires screenshot review; build passing does not certify that. No changes to persistence schema or API behavior.

## 0.7.0 — workspace shell

Official React Resizable, Dialog, Menu, Tooltip and Tree references consulted before edits. Desktop library and inspector now participate in a horizontal Resizable with saved layout; compact overlay is retained separately. Tree groups character and asset records, track creation uses Menu, navigation uses Tooltip, and JSON export uses Dialog. Version is exposed via /api/version and the main element. Deployed smoke had timed out on the exact Format accessible label; locator now scopes an explicit compatibility fallback to the project form and does not bypass the interaction. An independent deployment identity test requires the new endpoint and matching page version. Neither an old deployment nor a failed remote test certifies the new source. Screenshot artifact generation is not visual approval. Remaining: inspect actual screenshots, clean domain CSS, and implement timeline/core and visual builder behaviors. No project schema changes.

Visual QA: directly inspected CI screenshots from 41f4487 and 949560b (comic and editor). The portrait sheet exceeded the standard desktop viewport; adjusted fit using the actual page aspect ratio and added a bounding-box assertion. The deployed functional smoke passed after correcting the Format locator; the independent version endpoint assertion failed, so deployment identity is not established. Version test now also checks equality with source package version and runs on local build.

## 0.8.0 — comic canvas interaction slice

Official [direct manipulation](https://ui-sdk.dev/docs/core/behaviors/direct-manipulation), [selection](https://ui-sdk.dev/docs/core/behaviors/selection) and [primitive](https://ui-sdk.dev/docs/core/kernel/define-a-primitive) docs reviewed. Replaced the comic sheet's raw bindDrag with an SDK primitive composed from createResize (move, edges, corners) and createSelection (single selection). React parts expose accessible handles and live drag styles. Geometry is converted between measured display pixels and normalized page data, preserving schema; only completed edits are persisted. Multi-selection/lasso, group move, pan/zoom via createViewport, layers and undo/redo remain separate work. Fixed the ESM Playwright package JSON import by reading with fs, so the viewport and deployment tests can actually execute. Browser tests added; verify CI before calling this complete.

## 0.10.0 — canvas view and page edit history

Consulted official UI SDK Canvas, Dragging and Resizing, Handle Changes, Toolbar and Tree guides. Canvas uses createViewport for background pan, wheel/keyboard zoom, and toolbar zoom/reset. Geometry uses unscaled sheet dimensions and createResize.scale, keeping normalized project data independent of viewport. Resizing the workspace or switching pages resets view to fit. Page edits use createUndoStack (50 steps per page, in-memory during the mounted Production workspace); layer ordering follows the panel array and export paint order. The layer tree selects the actual canvas panel; duplicate, forward/backward, undo/redo use SDK toolbar controls. Page order is not included in per-page history; neither are assets or story changes. Multi-select/group movement and lasso remain pending. Added browser tests for pan/zoom, layer order, history and actual example timeline WebM container bytes. No storage schema change.
